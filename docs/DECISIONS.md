# Decisions

1. Data source pivot (2026-10-17). The Bundesagentur Jobbörse is excluded by its terms (DATA_TERMS.md), and I ruled out manual collection and sources that need registration. Sources checked without registration:
   - Arbeitnow free job board API (https://www.arbeitnow.com/api/job-board-api): offered publicly to third parties, no key, robots.txt allows all; terms ask for a link back, allow revocation, and limit site materials to non-commercial use with no public display. Full HTML descriptions (median about 4,800 characters in a probe of 1,664 postings), about 26 percent of them in German locations, with roughly a week of history visible (pages ran to about 35). **Chosen as primary source.** Our use is non-commercial, stored privately, with only aggregates published, which fits these terms.
   - Hugging Face `mischeiwiller/german-job-postings` (CC-BY-4.0, 70,584 rows): titles and metadata only, with no description text, and itself harvested from the Bundesagentur interface. Rejected: no text, and it would route around the Bundesagentur terms.
   - SmartRecruiters public posting feeds (no key): intended for companies' own career sites, and coverage dominated by a few employers (Bosch 774 German postings). Rejected.
   - Greenhouse and Personio public boards: per company, few German postings, no way to discover companies at scale (the Common Crawl index timed out). Rejected for now.
   - Web Data Commons JobPosting tables (about 3.06 million rows, 2020 extraction, published "for research purposes", no explicit licence): possible historical supplement, not used for now.
   - ESCO web service API works without a key (verified with a live query).
   Consequences: corpus size grows through weekly snapshots instead of a single 20,000-posting harvest; Arbeitnow tags replace Bundesagentur occupational fields as classifier labels (noisier); the Rhine-Main and Rhine-Neckar view depends on how many postings fall there.
2. Crawler scope: employer career sites listed by Web Data Commons (2020 JobPosting statistics, `.de` hosts with at least 5 rows), with job boards, staffing agencies and media excluded by host-name rules (`harvest/policy.py`). Each host: robots.txt obeyed, TDMRep reservation (`/.well-known/tdmrep.json`, page meta tag) honoured, at most one request per 5 seconds, job URLs only from the host's sitemaps, only schema.org JobPosting JSON-LD with a German address kept. Gzipped sitemaps and microdata markup are skipped (simplicity). Resumption relies on the per-snapshot response cache instead of a separate task table.
3. Crawl concurrency: the first full crawl ran hosts round robin in one thread and would have taken days; it was restarted with 16 worker threads (one host per worker), keeping the per-host interval.
4. Redaction: whole-text person-name NER was tried and rejected because it removed product names ("Claude Code", "Instagram Reels", "NVIDIA Isaac Sim"). Names are removed by salutation and role-title rules everywhere and by cue rules plus spaCy person entities inside contact blocks, with a filter for multi-word capitalised names that contain no pronoun or role word.
5. Gold set: 200 postings (120 German, 80 English; stratified by first Arbeitnow tag), requirement section (tasks when no requirements section), capped at 1,200 characters, split alternately into 100 dev and 100 test. Single annotation pass by a language model; a second independent pass was not possible inside one session, so no agreement is reported (spec asked for two passes). Gold texts were later re-redacted and the Arbeitnow footer removed; every annotated span was checked to survive.
6. Gazetteer matching uses a token n-gram dictionary over lower-cased surface and lemma keys instead of spaCy PhraseMatcher, to index both forms with one structure. Single-word ESCO labels tagged as verbs, adjectives or other non-nouns are skipped.
7. Aggregator rule: host-name rules alone let job boards through (for example Absolventa, Adzuna, Careerjet, Experteer). A crawled host whose JobPosting markup names more than 3 hiring organisations is treated as a job board or agency feed: the crawler stops on it and the corpus build excludes its postings, including those fetched before the rule existed. The cached pages remain on disk (the build rules forbid deleting downloaded data); they are not used.
8. Mining fixes after reviewing the first mined list: slash compounds (CI/CD, S/4HANA) kept whole, language levels (C1, B2) and broken compound fragments ("Wirtschafts-") rejected, stop list extended with nouns that were frequent noise ("Wort", "Schrift", "Menschen", "Planung").
9. Execution environment: on 2026-10-18 and again on 2026-10-22 Windows Smart App Control (enforced) started blocking unsigned compiled modules in the virtual environment (pydantic-core, pyarrow, a mypy module) that had loaded before. No security setting was changed. Every step from then on runs in a Linux development container (`docker/Dockerfile.dev`, `scripts/dev.ps1`, `scripts/run_pipeline.ps1`) with the project folder mounted; the container uses the same pinned requirements. One container at a time: the Docker VM has 3.5 GB of memory and failed once when two ran together.
10. Section splitter evaluation: 100 real postings outside the gold set (60 Arbeitnow, 40 career sites), every short non-bullet line labelled with the section it opens or "none". Postings s000 to s049 were used to extend the cue lists and heading rules (word boundaries, "Key: value" lines are not headings, bold sentences over 12 words are not headings); s050 to s099 were held out. Both the baseline and the improved scores are kept in `results/section_splitter_eval.json`.
11. Redaction refinement found while labelling: staffing-agency postings put the contact name on its own line next to the role ("Personaldisponentin"). New rules: contact windows reach two lines before and after a cue (the preposition rule only after the cue); a line that is only a name is removed when a neighbouring line is a role title, or when both spaCy models tag it as a person (one model suffices in the last six lines, where contact details sit). Checked on the splitter sample and the gold texts: five real names removed, no other line changed, no gold span lost.
12. Demand for the CV tool: the share of the 100 corpus postings whose skill sets overlap most with the job's (Jaccard) that mention a skill. Chosen over a classifier-based "same field" definition because the platform labels are noisy and absent for career-site postings.
13. Staffing agencies are identified by words in the employer name (Personal, Zeitarbeit, Vermittlung, Recruit, and known agency names); a heuristic used only for the robustness check that recomputes shares without them.
14. Trend test: the publication window is split at its median date; a skill with at least 20 mentions is flagged when the bootstrap interval of its share difference excludes zero, reported both without correction and with a Bonferroni correction for the number of skills tested.
15. Classifier code moved from the CLI into `classify/experiment.py`; results from separate runs are merged so a BERT-only run (as in Colab) keeps the baselines, and test-set probabilities are saved for the paired comparison.
16. Extraction rework after inspecting matches at corpus scale (2026-10-22). The first tuned configuration (results kept in `results/extraction_eval_v1.json` and `results/extraction_tuning_v1.json`; its test half had been evaluated once) produced market tables headed by fragments and generic words: single-word English alternative labels of unrelated ESCO skills ("data" for Statistik, "design" for "kreativ denken", "standards" for Gerüstteile), a letterless ESCO label "?", adjectives and task nouns mined from bullet lists ("Strukturierte", "Ansprechpartner"), lemma matches of mined names ("control" for Controlling) and fragments rewarded by the partial-span objective ("Arbeitsweise"). Changes: single-word alternative labels kept only when tool-like; letterless labels dropped; bullet items mined only from requirement sections; mined terms cut at function words, filtered for single-word adjectives and for compounds that already resolve to a skill, and matched on surface form only; tuning objective and blocking criterion switched from partial-span to skill-set correctness. These changes were motivated by corpus-level inspection, not by test-half errors; the test half was then evaluated a second time and both evaluations are reported.
17. Market fixes: NMF stability now uses random initialisation (the SVD-based start ignored the seed, so the earlier agreement of 0.999 measured nothing); the trend test runs per source within the last 100 days (career-site publication dates go back years, so a pooled median split compared sources, not time).
18. BERT budget: the first local run (2 epochs, 144 optimiser steps) did not converge: validation loss fell only from 2.24 to 2.15 (chance level for 12 classes is about 2.48) and validation macro-F1 stayed under 0.10 (archived in `results/classifier_results_bert_2epochs.json`). Decided on the validation split, not the test split: 5 epochs, 10 percent learning-rate warm-up, early stopping after two epochs without improvement.
19. Publication dates (found while checking the corpus statistics, 2026-10-28): the corpus build cut JSON-LD `datePosted` to 10 characters, which works for ISO dates but turned "Mar 01, 2025" into "Mar 01, 20" for 77 of 3,924 crawl postings; those postings then dropped out of the trend test and corrupted the date range in `corpus_stats.json`. `parse_published` now reads ISO, English ("Mar 01, 2025"), German ("24. August 2025") and dotted ("24.08.2025") forms and returns None for anything else. Instead of a full rebuild, which would rerun redaction and could shift texts the gold set and classifier splits refer to, `scripts/fix_published.py` recomputed only that column from the raw store (exactly the 77 rows changed); `jobnlp market` was then rerun.
